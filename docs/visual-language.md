# Life Timer 视觉语言方案

本方案按 `frontend-design` skill 生成，用于约束 Life Timer 后续界面设计、重构和组件扩展。

> **v2 修订说明**：在保留原有设计主张（安静仪表、Drain Bar / Days Ring / History Timeline）和明暗主题的"日暖夜冷"物理场景设定基础上，色板整体转向更浓的"墙面纸台账"walnut 色调（色相从 75–88 收拢到 46–66），状态色收深为更沉稳的"火漆封印"色系；新增仪表刻度（Meter Ticks）作为唯一的一处视觉冒险，应用于 Days Ring 与状态汇总条；数字启用 `tabular-nums`。所有改动均通过既有 `--lt-*` token 落地，未新增字体、未引入玻璃拟态或装饰动画。

## 设计前提

具体对象：一个给个人使用的生活倒计时与消耗预估工具。  
典型场景：用户在家中用手机快速检查，确认有没有域名、车险、证件或水电余额需要关注。  
页面单一任务：5 秒内回答“有没有需要处理的事情”。

视觉关键词：安静、精准、私人仪表。  
不做：企业后台、监控大屏、SaaS 运营台、霓虹深色面板。

## 设计主张

Life Timer 不应该像任务管理软件，而应像一个放在书桌边的低噪声仪表：平时安静，只有接近耗尽或到期时用颜色和比例轻轻提醒。

界面重点不是“数据很多”，而是“剩多少”这个判断动作。Drain Bar、天数圆环、时间范围历史，是视觉语言的核心。

## 色彩系统

策略：Restrained，温暖浅色 + 冷静深色 + 低面积语义色。颜色只用于状态和当前选择，不做装饰。

深色主题保持"冷灰蓝夜间面板"设定，本次修订未改动其中性色阶，仅将下方状态色的色相与浅色主题对齐，确保语义在两个主题间完全一致。

### 状态色

状态色由"糖果绿/橙/红"收深为更接近"火漆封印"的沉稳色系，两个主题共用同一份数值（不随主题改变含义），并额外提供一组更深的 `-deep` 变体供图表细线等浅色背景上使用。

| 状态 | 名称 | Token | 值（OKLCH） | 使用 |
|---|---|---|---:|---|
| 正常 | Patina Green | `--lt-ok` | `oklch(60% 0.135 147)` | 剩余充足、正常段 |
| 预警 | Brass Amber | `--lt-warn` | `oklch(63% 0.175 58)` | 接近阈值 |
| 紧急 | Sealed Vermilion | `--lt-danger` | `oklch(55% 0.196 23)` | 即将耗尽或过期 |
| 已过期 | Muted Stone | `--lt-expired-color` | `oklch(52% 0.022 58)` | 已失效但不制造警报感 |

状态色原则：

- 绿色、橙色、红色只出现在进度、圆环、状态摘要、小角标中。
- 禁止把整张卡染成高饱和状态色。
- 状态色必须配合文字标签，如“正常”“预警”“紧急”“已过期”。
- 组件中不再手写状态色的 OKLCH 字面量，统一引用 `var(--lt-ok)` / `var(--lt-warn)` / `var(--lt-danger)` / `var(--lt-expired-color)`（及 `-deep` 变体），保证未来只需改一处 token。

## 字体系统

Life Timer 是产品 UI，优先系统字体，减少加载成本。

| 角色 | 字体 | 用途 |
|---|---|---|
| 界面主体 | `-apple-system, BlinkMacSystemFont, "Segoe UI", system-ui, sans-serif` | 所有正文、按钮、表单 |
| 数据数字 | 同主体字体，使用 `font-variant-numeric: tabular-nums` | 天数、百分比、示数 |
| 辅助标签 | 同主体字体，中等字重、较小字号 | 标签、历史记录、状态摘要 |

`tabular-nums` 现由 `body` 统一声明（`globals.css`），全站生效，不需要在组件层单独设置。

字号建议：

- 页面标题：32px，700，紧凑字距。
- 卡片标题：22px，700。
- 主数字：28 到 34px，700，tabular nums。
- 正文说明：13 到 14px。
- 标签与历史辅助文案：11 到 12px。

## 布局语言

移动优先，桌面只增加呼吸感，不改变核心结构。

```
┌────────────────────────────┐
│ Life Timer        actions  │
│ user / admin / logout      │
├────────────────────────────┤
│ [ 到期提醒 ] [ 消耗预估 ]   │
│ search                     │
│ status summary + drain     │
├────────────────────────────┤
│ card                       │
│  tag                       │
│  name            days ring │
│  date                      │
│  drain bar                 │
│  accordion history/actions │
└────────────────────────────┘
```

原则：

- 卡片之间保持明显间距，卡片内部保持紧凑信息密度。
- 历史记录采用手风琴模式，同一列表只展开一项。
- 展开内容是附属信息，不应抢走主卡片的判断任务。
- 桌面最大宽度保持克制，避免横向铺满导致扫视成本变高。

## 标志性元素

签名元素：Quiet Drain Instrument。

它由三部分构成：

1. Drain Bar：表达"剩余比例"，比文字警告更先被感知。
2. Days Ring：表达"剩余天数"，形成快速判断锚点。
3. History Timeline：表达"这件事如何续期或如何变化"，用于追溯而非首屏主视觉。

这个元素要像仪表，不像游戏血条。颜色变化要温和，线条要稳定，动画只用于数值进入和展开收起。

### 仪表刻度（Meter Ticks）— 唯一的一处视觉冒险

Days Ring 的轨道外侧、状态汇总条内部各增加固定的 25% / 50% / 75% 刻度线（`--lt-tick` / `.lt-status-tick`）。这不是装饰：一半的物品本身就是真实的水表、电表，刻度是它们本来就有的读数方式；对到期提醒同样适用，因为用户判断的始终是"大概还剩几分之几"而不是精确读数。刻度是静态的、不参与动画，颜色取自极低透明度的中性色，任何主题下都只起到"参照网格"的作用，不会喧宾夺主。这是本方案唯一主动选择的视觉冒险点，其余部分保持克制。

## 动效规范

- 展开/收起：150 到 220ms，ease-out，传达层级变化。
- 数值进度：首次渲染可轻微补间，不循环。
- hover：只改变表面、阴影或轻微位移。
- 禁止无意义漂浮、呼吸光、背景粒子。
- 尊重 `prefers-reduced-motion`。

## 组件语气

文案要像冷静助手，不像营销产品。

推荐：

- “历史记录”
- “初始时间范围”
- “由 2026年7月31日 - 2028年7月31日 续期而来”
- “预计还剩 24 天”
- “录入第一条示数开始追踪”

避免：

- “立即处理！”
- “风险爆表”
- “超强智能预测”
- “提交”

控件名必须描述动作结果：`保存`、`确认续期`、`录入`、`恢复`、`删除`。

## 视觉风险点

本方案保留一个可控风险：浅色主题使用温暖纸感，而深色主题使用冷灰蓝。两者不是简单反色，而是适配不同环境的两种物理场景。

风险控制：

- 所有语义色保持一致，不因主题改变含义。
- 深色主题的活跃控件不使用奶油白大色块，使用 elevated slate。
- 浅色主题不使用纯白和纯黑，避免廉价对比。

## 自检清单

修改 UI 前后检查：

- 用户 5 秒内能否判断有没有需要关注的条目。
- 主视觉是否仍然是剩余比例和剩余天数，而不是按钮、装饰或图表。
- 是否新增了未 token 化的颜色。
- 状态是否同时有颜色和文字。
- 移动端 44px 触控面积是否保持。
- 展开内容是否只展示一个，是否影响扫视效率。
- 深色主题是否使用冷灰层级，避免高饱和霓虹。
- 空状态和错误状态是否给出下一步，而不是只说“暂无”。
